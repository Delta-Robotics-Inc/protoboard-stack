# Wearable watch: brief

Reference project for the Protoboard Stack. It exercises the
two workflows the quadcopter avoided: a custom PCB (`circuit` capability) and a
custom enclosure (`cad` capability).

Hardware defaults agreed on 2026-10-02. Parts, sources and reasons:
[component selection](component-selection.md). Rails and battery life:
[power budget](power-budget.md). Block diagram and pin map:
[system](system.md). Decisions left for later tracks:
[open questions](open-questions.md).

Every number below is either cited in those documents or marked as an
assumption or a target. A target is a requirement we set; it is not a
measured or datasheet value.

## Purpose

A small, open, fully described smartwatch: a round colour display, motion and
heart-rate sensing, haptic alerts and Bluetooth LE to a phone. It shows how a
custom board and a printed case are described in UHD, generated by providers
and kept consistent with the parts they hold.

## Users

- **Engineers evaluating Protoboard Stack.** They read the project, run the
  checks and open the board and case in the viewer.
- **The agents and engineers who build the later tracks** (parts research,
  board, enclosure, firmware). This brief and its companions are their input.
- **A wearer** in the use cases below. Nobody wears this build: it is not
  physically made in v0.1.

## Functions

| ID | Function | Hardware |
| --- | --- | --- |
| F1 | Show time, notifications and sensor readings on a 1.28-inch round 240×240 colour display | ER-TFT1.28-1 (GC9A01), SPI |
| F2 | Count steps and detect wrist raise to wake the display | BMI270 accelerometer features |
| F3 | Measure heart rate (and SpO2 as a raw signal, not a medical value) on demand and periodically | MAX30102 through a window in the back cover |
| F4 | Vibrate for alerts and confirmations | DRV2605L + 8 mm LRA |
| F5 | Exchange data with a phone over Bluetooth LE | nRF52840 module |
| F6 | Report battery state of charge | MAX17048 |
| F7 | Charge from USB-C, and update firmware over USB | MCP73831, USB-C receptacle, nRF52840 USB |
| F8 | Two buttons on the case side: wake/select and back | 2 × side-push tact switches |

## Targets

| Target | Value | Basis |
| --- | --- | --- |
| Battery | One LiPo cell, about 200 mAh | Agreed default; selected cell: 200 mAh, 4.0 × 20 × 30 mm |
| Battery life, typical use | ≥ 5 days | Target. Estimate 12 days under the duty-cycle assumptions in [power budget](power-budget.md); the margin covers the assumptions not yet measured |
| Battery life, standby (BLE connected, screen off) | ≥ 30 days | Target. Estimate about 120 days before self-discharge |
| Charge time | ≤ 3.5 h from empty | Target. 83 mA charge current (below the cell's 100 mA limit) gives about 2.4 h of constant current plus the taper |
| Charging | USB-C 5 V, no USB Power Delivery | Agreed default (USB-C or pogo pins; USB-C chosen, see open questions) |
| Case envelope | Round case body ≤ 46 mm diameter (lugs excluded), ≤ 13.5 mm thick, 22 mm between lugs | Target. The display module alone is 35.60 × 37.80 × 1.5 mm with its FPC folded |
| Weight | ≤ 40 g without strap | Target. Estimate in [component selection](component-selection.md#mass-estimate) |
| Ingress | Splash resistant (rain, hand washing). No IP rating is claimed and none is tested | Stance. A 3D-printed case and an open USB-C receptacle cannot be claimed waterproof without testing |
| Strap | Standard 22 mm two-piece strap on 1.5 mm spring bars | Agreed default |
| Operating temperature | 0 °C to 40 °C | Target, inside every selected part's range; the cell charges only from 0 °C to 45 °C |

## Constraints

- **Agreed hardware.** nRF52840 module (BLE), 1.28-inch round 240×240
  display, BMI270, MAX30102, DRV2605L with an LRA, about 200 mAh LiPo with
  charger and fuel gauge, USB-C or pogo-pin charging, two buttons, custom PCB,
  3D-printed case, 22 mm strap pins.
- **Purchased, current parts only.** Every purchased part has an exact
  manufacturer part number and a cited source. No part marked
  not-recommended-for-new-designs is chosen.
- **Manufacturable by a standard PCB assembly service.** Parts that need hand
  assembly (the display's solder-tab FPC, the battery and LRA leads) are
  named as such.
- **Pre-certified radio.** The radio is a certified module, so the board does
  not need its own RF design. Antenna keep-out rules from the module maker
  apply to the board and the case.

## Project rules for this build

These govern how the project is made, not the watch itself, so they are not
in the test plan.

- **UHD stays tool-neutral.** The board and case are UHD modules; footprints,
  layer stacks and CAD feature trees live in the provider directories, never
  in UHD (see [tool integrations](../../../docs/specs/tool-integrations.md)).
- **No real-world actions.** No orders, fab uploads or prints in v0.1.

## Out of scope

- Medical claims. Heart-rate and SpO2 numbers are for demonstration only.
- Physical build, bench tests and wear tests.
- Phone app and the BLE service definitions beyond what the firmware track
  needs for a demo.
- Touch input, microphone, speaker, GPS, NFC payments, cellular, Wi-Fi.
- Water resistance ratings, drop tests, regulatory certification of the
  finished product (the module carries its own radio certification).
- Wireless (Qi) charging and a charging dock.

## Acceptance for this reference build

The build is accepted when the project holds manufacturing-ready files and
the checks pass. It is not built physically.

1. `protoboard check` passes on the watch project with no errors.
2. Every purchased part is a UHD part in the right tier (catalog or
   `parts/local/`), with evidence and an acceptance report like the
   quadcopter's parts.
3. The main board is a UHD module whose nets are links between its
   components. The `circuit` provider generates it and exports Gerber +
   drill, BOM and pick-and-place keyed by UHD instance path, board GLB/STEP
   and a geometry manifest. `check` reports no drift between board and UHD.
4. The case is a UHD module holding the interfaces it must hold (display,
   buttons, USB-C, sensor window, battery, strap bars, screws). The `cad`
   provider generates STEP/GLB, printable STL/3MF and a geometry manifest.
5. The assembled watch (board, case, display, battery, LRA, strap bars) shows
   in the viewer with labels, and every harness (battery leads, LRA leads) has
   routed geometry.
6. The power budget is recomputed from the UHD model's parts and matches this
   brief's estimate, or the brief is updated.
7. Stand-in data (any value not yet measured) is labelled as such in every
   generated document.
